## Главное меню

Точка возврата из любого раздела. Reply-клавиатура, 5 рядов:

```
[ 🧩 Автоматизация ] [ 📈 Кейсы маркетинга ]
[ 🎯 Бесплатный аудит ]
[ 📰 Digital digest ] [ 📞 Контакты ]
[ ℹ️ Инструкция ] [ 🔄 Перезапустить ]
[ 🇷🇺🇬🇧🇷🇸 RU/EN/RS ]
```

| RU | EN | SR | intent_key |
|----|----|-----|------------|
| 🧩 Автоматизация | 🧩 Automation | 🧩 Automatizacija | `menu_usecases` |
| 📈 Кейсы маркетинга | 📈 Marketing cases | 📈 Marketing studije | `menu_marketing_cases` |
| 🎯 Бесплатный аудит | 🎯 Free audit | 🎯 Besplatan audit | `lead_audit_request` |
| 📰 Digital digest | 📰 Digital digest | 📰 Digitalni pregled | `menu_hot_news` |
| 📞 Контакты | 📞 Contacts | 📞 Kontakti | `menu_contacts` |
| ℹ️ Инструкция | ℹ️ Instruction | ℹ️ Uputstvo | `menu_instruction` |
| 🔄 Перезапустить | 🔄 Restart | 🔄 Pokreni ponovo | `start` (перезапуск онбординга) |
| 🇷🇺🇬🇧🇷🇸 RU/EN/RS | то же | то же | `change_language` |

Навигационные кнопки в подменю:

| RU | EN | SR | intent_key |
|----|----|-----|------------|
| ⬅️ Назад | ⬅️ Back | ⬅️ Nazad | `back` |
| 🏠 Главное меню | 🏠 Main Menu | 🏠 Glavni meni | `main_menu` |
| 🧹 Сбросить память | 🧹 Reset Memory | 🧹 Resetuj memoriju | `reset_memory` |

Подписи всех кнопок хранятся в одном месте — `menu_labels` узла `Set - Runtime Limits And Variant Config`. Если подпись меняется, её нужно добавить и в точную карту `Code - Resolve Intent Key`, иначе нажатие не распознается.

## Командная система

Команды, текст кнопок и callback разрешаются кодом (см. `bot-architecture` → «Разрешение intent»).

| Команда | intent_key |
|---------|-----------|
| `/start`, `/start <метка>`, `/restart` | `start` → приветствие + онбординг с шага 1 |
| `/menu` | `main_menu` |
| `/help` | `menu_instruction` |

Нераспознанный ввод вне диалога с AI → fallback-сообщение с главным меню.

## Модуль: Заявка на бесплатный аудит

Основной способ передать пользователя владельцу.

**Точки входа**: кнопка «🎯 Бесплатный аудит» в главном меню, inline-кнопка в AI-бридже онбординга, верхний ряд клавиатуры под каждым ответом AI, текст «аудит».

### Сценарий

1. **`lead_audit_request`** — бот показывает экран подтверждения: что он уже понял из ответов цепочки (метки трёх ответов), совет сначала описать бизнес одним сообщением, вопрос «Отправить это Дмитрию как заявку на аудит?». Inline-кнопки: «✅ Отправить заявку» (`lead_audit_confirm`), «🏠 Главное меню». Если заявка уже подавалась в течение часа — экран об этом предупреждает.
2. **`lead_audit_confirm`** — создаётся запись в `lead_requests` с типом `audit_request` и профилем в заметках. Повторное нажатие в течение часа новую заявку не создаёт.
3. **Подтверждение пользователю** — зависит от того, можно ли ему написать:
   - есть username или сохранён телефон → «заявка у Дмитрия, он напишет вам лично в Telegram»;
   - нет ни того, ни другого → бот объясняет, что владелец может не суметь написать первым, и показывает кнопку **«📱 Отправить мой номер»** (Telegram `request_contact`) либо предлагает написать самому на @kovachinfo.
4. **Уведомление владельцу** — см. «Уведомления о лидах».

### Передача телефона

Нажатие «📱 Отправить мой номер» приходит как `input_type = contact` → intent `lead_contact_shared`:

- номер сохраняется в `onboarding_profile_json.contact_phone` (ответы цепочки не затрагиваются) и в `contact_preference` последней заявки пользователя (`phone: +…`);
- пользователь получает подтверждение и главное меню;
- владельцу уходит отдельное уведомление с номером (Telegram + email).

Телефон сохраняется при перезапуске онбординга.

## Модуль: Уведомления о лидах

Получатели в Telegram — все пользователи с `bot_users.is_admin = TRUE`; дополнительно письмо на почту владельца.

| Событие | Когда срабатывает | Каналы |
|---------|-------------------|--------|
| Лид онбординга | Пользователь после цепочки прислал настоящее описание бизнеса (см. `onboarding-funnel` → «Захват описания бизнеса») | Telegram + email |
| Заявка на аудит | Подтверждена заявка (`lead_audit_confirm`), не дубль за последний час | Telegram + email |
| Передан телефон | Пользователь поделился номером | Telegram + email |

Само по себе завершение цепочки уведомление **не** вызывает.

### Содержимое карточки

Telegram-карточка отправляется в HTML-разметке, значения экранируются. В ней:

- имя, username, id и язык; если username нет — ссылка `tg://user?id=…`;
- телефон, если передан;
- источник (`entry_point`);
- все ответы цепочки в виде «вопрос — ответ» (три строки);
- потенциальная услуга;
- текст описания бизнеса, если есть;
- номер заявки.

Текст письма и карточки собирается одной общей функцией, поэтому содержимое в обоих каналах одинаковое.

## Модуль: AI-ассистент

**Где работает**: состояние `ai_entry` (после онбординга) и `creative_chat` (раздел консультации). Весь нераспознанный свободный текст в этих состояниях идёт в AI (`ai_default`).

**Модель**: OpenAI `gpt-5.4-mini` через n8n AI Agent.

**Роль**: ассистент Дмитрия, говорит о нём в третьем лице. Знает оффер (полный цикл в одних руках) и профиль пользователя из цепочки. Единственный способ передать пользователя владельцу — кнопка заявки на аудит; ассистент не обещает звонков и не выдумывает других каналов.

**Контекст, который получает ассистент**:

- `lead_stage` — стадия лида (`awaiting_description` / `just_described` / `described` / `no_onboarding`);
- `audit_requested` — подана ли заявка на аудит (чтобы не предлагать её повторно);
- профиль из онбординга и текст описания бизнеса.

В пользовательский промпт попадает только текст сообщения — без служебных вставок.

**Возможности и ограничения**:

- **Текст и голос**: голосовое → Groq `whisper-large-v3` → текст → AI → ответ текстом. Голосовое — до 120 секунд, квота общая с дневным лимитом AI; при превышении и при неудачном распознавании пользователь получает отдельное сообщение.
- **Память**: Postgres Chat Memory (`n8n_chat_histories`), ключ — `user_id`, окно 30 сообщений.
- **Сброс памяти**: кнопка «🧹 Сбросить память» (`reset_memory`).
- **Лимит**: 30 запросов за 24 часа на пользователя (`ai_daily_limit`), считается по событиям `ai_request` в `bot_events`. При превышении — уведомление с отсылкой к заявке на аудит и контактам.
- **Блокировка**: пока идёт генерация ответа, новые запросы того же пользователя не запускаются (`ai_lock_seconds` = 120).
- **Длина ответа**: до 1800 символов (`ai_max_chars`).

**Клавиатура под ответом AI**:

```
[ 🎯 Бесплатный аудит ]
[ 🧹 Сбросить память ] [ 🇷🇺🇬🇧🇷🇸 RU/EN/RS ]
[ ⬅️ Назад ] [ 🏠 Главное меню ]
```

Каждый запрос логируется в `bot_events` (`ai_request`) с типом ввода, состоянием, длиной и стадией лида.

## Модуль: Кейсы маркетинга

**Intent**: `menu_marketing_cases` → список кейсов inline-кнопками; `marketing_case` (callback `mcase_<item_key>`) → карточка кейса.

**Контент**: `bot_content_items`, module_key = `marketing_cases`. Наполнение — миграция `kovach_bot_migration_marketing_cases.sql`. Список и карточки строятся из базы, поэтому кейсы добавляются без правки workflow (список рассчитан на 1–12 кейсов, альбом — до 10 изображений).

**Медиа**: скриншоты загружены через `Kovach Bot - Case Media Loader`, отправляются как фото или альбом.

## Модуль: Автоматизация (юзкейсы)

**Intent**: `menu_usecases` → подменю из 6 карточек, названных по нишам. Заход: «Как бот и автоматизация работают в разных нишах. Выберите ближайшую к вам:».

| intent | RU | EN | SR | Заголовок карточки (RU) |
|--------|----|----|----|-------------------------|
| `case_1` | ⚖️ Юрист | ⚖️ Lawyer | ⚖️ Pravnik | Миграционный юрист: квалификация и запись на консультацию |
| `case_2` | 🔧 Монтаж отопления | 🔧 Heating installation | 🔧 Montaža grejanja | Ремонт и монтаж отопления: приём заявок и запись на выезд |
| `case_3` | 💆 Косметолог | 💆 Cosmetologist | 💆 Kozmetolog | Косметолог: ответы на вопросы, подготовка и напоминания |
| `case_4` | 🪑 Мебель на заказ | 🪑 Custom furniture | 🪑 Nameštaj po meri | Изделия из массива на заказ: отсев нецелевых и сбор параметров |
| `case_5` | 🏢 Недвижимость | 🏢 Real estate | 🏢 Nekretnine | Агент по недвижимости: свободен ли объект и подбор похожих |
| `case_6` | 👗 Шоурум одежды | 👗 Fashion showroom | 👗 Modni showroom | Бренд одежды и шоурум: наличие, размеры и возврат к покупке |

Карточка: заголовок (ниша + что автоматизируется), затем «Что продаёт», «Каналы коммуникаций», «Боль», «Что автоматизировать». Имён вымышленных героев в карточках нет. Тексты зашиты в узлы `Telegram - Send Case N Skeleton`.

**Распознавание нажатий.** Названия ниш — обычные слова, которыми пользователь может описать свой бизнес («Юрист», «Недвижимость»). Поэтому кнопка засчитывается только если текст пришёл вместе с эмодзи кнопки (таблица `nicheButtons` в `Code - Resolve Intent Key`); набранное руками слово без эмодзи уходит AI-ассистенту. Старые подписи «Юзкейс №N» продолжают распознаваться — у пользователей может оставаться закэшированная клавиатура.

## Модуль: Digital digest

**Intent**: `menu_hot_news` → последняя опубликованная запись из `hot_news_digests` на языке пользователя. Длинный дайджест режется на части меньше лимита Telegram (4096 символов); меню прикрепляется к последней части.

### Жизненный цикл дайджеста

```
draft → pending_approval → approved → published
                          ↘ rejected (конец)
```

### Админ-панель (Human In The Loop)

Workflow `Kovach Bot - Digest Admin (Human In The Loop)` вызывается из основного через `Execute Workflow - Digest Admin` по intent `hotnews_action`. Доступ — только для администраторов (проверка прав в базе); остальным приходит отказ.

1. AI генерирует дайджест на заданном языке.
2. Черновик отправляется ревьюеру в Telegram с кнопками [Approve / Reject].
3. После утверждения запись получает статус `approved`.
4. Публикация — отдельное действие (статус `published`).

### Структура `hot_news_digests`

| Поле | Тип | Назначение |
|------|-----|-----------|
| `lang` | text | Язык дайджеста (ru/en/sr) |
| `title` | text | Заголовок |
| `digest_text` | text | Текст дайджеста |
| `source_links_json` | jsonb | Источники |
| `status` | enum | draft / pending_approval / approved / rejected / published |
| `approved_by` | bigint | ID утвердившего |
| `published_message_id` | bigint | ID сообщения в канале после публикации |

## Модуль: Смена языка

**Intent**: `change_language`.

| RU | EN | SR | intent_key |
|----|----|-----|------------|
| 🇷🇺 Русский | 🇷🇺 Russian | 🇷🇺 Ruski | `set_lang_ru` |
| 🇬🇧 English | 🇬🇧 English | 🇬🇧 Engleski | `set_lang_en` |
| 🇷🇸 Srpski | 🇷🇸 Serbian | 🇷🇸 Srpski | `set_lang_sr` |

После выбора `bot_users.language` обновляется, пользователь получает главное меню на новом языке. Текущее состояние онбординга не теряется.

## Human Handoff — не реализовано

Задуманная модель — proxy-bot через Telegram Topics (один клиент = один топик в менеджерской супергруппе, таблица `chat_sessions`). В V7 это **заглушки**: узлы `Telegram - Manager Topic Relay Stub` и `Telegram - User To Manager Proxy Relay Stub` сообщения не пересылают.

Фактическая передача человеку сейчас: заявка на аудит → карточка владельцу → владелец сам пишет клиенту в Telegram (по username, по ссылке `tg://user?id=…` или по телефону).

## Модуль: Аналитика

Таблица `bot_events` — append-only.

| event_type | Когда пишется | Что в payload |
|------------|---------------|---------------|
| `onboarding_step` | Каждый шаг цепочки | `kind` (start / answer / resume / complete), `step`, `answer_key`, `answer_label`, `variant`, `language` |
| `ai_request` | Каждый ответ AI | тип ввода, состояние, длина, `lead_stage` |

Для событий хранятся `state_before` / `state_after`. Лиды — в `lead_requests` (`onboarding_v2`, `audit_request`), профиль и источник — в `bot_users`.
